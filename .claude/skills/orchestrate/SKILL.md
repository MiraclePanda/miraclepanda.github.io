# マルチエージェント・オーケストレーション

メインセッションがオーケストレーターとなり、AGENTS.md §5 の所有範囲に従って作業を配分する。

## 1. 分析(自分で行う)
- 要求を読み、影響する層を特定する。`Grep` で関係箇所を確認し、推測で分解しない
- 1層だけで閉じるなら委譲せず、担当エージェント1体か自分で直接実装する(並列化のコストに見合わない)

## 2. 契約を先に決める
層をまたぐ変更は、並列化の **前に** 以下を文章で確定する:
- `FtmsClient` のイベント名と `detail` の形(現在: `connected`, `disconnected`, `bike-data`, `control-mode`, `warning`, `communication-warning`, `command-error`)
- `PhysicsEngine.step()` の戻り値のキー
- ライド記録 `record` のスキーマ(IndexedDB 保存・TCX・Result/History 画面が共有)
- 新しい関数・props のシグネチャ

## 3. タスク表を作る
| # | 担当 | 対象ファイル | 内容 | 依存 |
|---|---|---|---|---|

- 同じファイルを2つのタスクに割り当てない
- 依存のないタスクは **1つのメッセージで複数の Agent 呼び出し** を行い並列実行する
- 依存のあるタスクは前段の完了報告を受けてから起動する

## 4. 委譲プロンプトのテンプレート
サブエージェントは会話履歴を持たないので、毎回これを埋めて渡す:
```
目的: <ユーザー要求のうちこのタスクが担う部分>
所有範囲: <編集してよいファイル>(範囲外は変更要求として報告)
契約: <§2 で確定した内容をそのまま貼る>
完了条件: <具体的な振る舞い> + `node harness/verify.mjs` が通ること + 必要なテスト追加
報告: AGENTS.md の完了報告フォーマット
```

## 5. 統合
1. 全タスクの報告を集め、「所有範囲外への変更要求」があれば担当に再委譲する
2. `verifier` に要求一覧を渡して検証させる。FAIL なら原因の担当に差し戻す(最大2往復。それ以上はユーザーに相談)
3. `code-reviewer` に差分レビューを依頼。[重大]/[中] は反映、[軽微] は判断してユーザーに共有
4. 自分でも `node harness/verify.mjs` と `git diff --stat` を確認する
5. ユーザーに報告: 変更概要 / 検証結果 / 手動確認が必要な項目(実機BLE・3D)/ 残課題
6. コミット・PR はユーザーの指示があってから。main に直接 push しない(ブランチ + PR)
